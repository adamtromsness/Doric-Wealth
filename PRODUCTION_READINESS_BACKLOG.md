# Production-Readiness Backlog

Output of a deep pre-review audit (UI cohesion, backend scale, frontend scale, correctness/hardening). The **Fixed in this pass** items are already applied; the **Deferred** items are larger/riskier refactors intentionally left for a focused follow-up (and the upcoming codex review), with file:line and recommended approach.

---

## Fixed in this pass

**Correctness / data-loss**
- `accounts.ts` `DELETE /:id` now 409s when the account has transactions/balances/holdings (was an irreversible cascade that orphaned transactions). Steers to archive/close.
- `imports.ts` staged confirm (single + bulk) now claims rows via `DELETE … RETURNING` inside the txn — a double-click/retry can no longer post the same CSV row twice (CSV rows have NULL external_id so the posted-txn unique index didn't protect them).
- `imports.ts` `parseDate` — DD/MM vs MM/DD disambiguation by value, 2-digit-year pivot (98→1998 not 2098), and no more UTC-shift fallback.
- `categories.ts` delete guard extended to **all** `ON DELETE SET NULL` referrers (added subscriptions, goals, utility_invoices, staged_transactions, transactions.interest_category_id) and made check+delete atomic.
- `books.ts` create wrapped in one transaction (no orphan book if the membership insert fails).

**Money precision** (`round2` on JS-summed totals that previously leaked sub-cent float noise)
- `networth.ts` (group + headline totals), `dashboard.ts` (headline totals + history series), `budgets.ts` (group/section rollups + uncategorized), `analysis.ts` (`computeNetWorth`).

**Scale hardening**
- New migration `124_scale_indexes.sql`: pg_trgm + `idx_txn_merchant_trgm`, `idx_txn_book_date`, `idx_txn_dedup`, `idx_txn_book_merchant`, `(id, as_of)` composites for property/asset/liability values, `idx_staged_book_account_decision`, `idx_receipts_book_purchased`.
- `db.ts` pool sets `idle_in_transaction_session_timeout=60s` (leaked-transaction pool-starvation defense).

**UI cohesion**
- Defined `--warn`/`--accent` CSS tokens (were undefined → off-palette goldenrod warnings across 7 files).
- Title Case sweep across buttons / field labels / table headers + list↔detail casing reconciliation (per the project Title Case convention).

**Follow-up pass (backup streaming + frontend pagination)**
- **Backup export now streams** (`backup.ts`): one shared `streamEnvelope` serializer pages each table by id (smaller batches for blob tables), base64s blobs per row, and writes the JSON to the response with backpressure — no full dataset/JSON string in memory. `buildEnvelope` (snapshot storage) now collects from the same serializer so the two can't drift. New round-trip tests cover the streamed `/export` route (valid JSON, import round-trip, selective groups). 80/80 tests pass.
- **Entity-detail transaction pagination** — `VehicleDetail`/`PropertyDetail` now use the shared `<Pager>` (server `pendingOffset`/`postedOffset`, `PAGE_SIZE`) instead of `limit=200`; `SubscriptionDetail`'s click-to-edit lookup pages through all charges; `AccountDetail` Overview capped to a page with the existing "View all" → (already-paginated) Transactions tab. No more silent row truncation.

## Deferred — recommended for the next pass / codex review

### A. Backend scale (large refactors)
1. ~~Backup export streams instead of one in-memory JSON string.~~ **DONE** (see follow-up pass above). Still remaining here: (a) snapshot *storage* (`storeSnapshot`) and `buildEnvelope` still materialize the full string because a snapshot is one `bytea` value — offload snapshot blobs to object storage to remove that residual memory ceiling; (b) `/groups` (`backup.ts:170-177`) full-scans + detoasts every blob via `pg_column_size` — use `octet_length`/`reltuples` estimates.
2. ~~Backup import is row-by-row INSERT…RETURNING~~ **DONE** — `restoreEnvelope` now prepares each table's rows, groups them by column signature, and writes chunked multi-row INSERTs (≤~60k params/statement) with RETURNING correlated positionally for id remapping; the self-ref second pass is unchanged. A new test verifies a category hierarchy's parent_id is remapped correctly through the chunked path. (Still worth doing later: run very large restores as a background job rather than in the request.)
3. **CSV confirm/staging row-by-row.** CONFIRM DONE — bulk confirm no longer calls `insertTransaction` per row; it claims rows (`DELETE … RETURNING`) then does a chunked multi-row INSERT, with the only real per-row side-effect (utility-invoice application) re-run just for rows whose category is a managed-utility category (prefetched). Safe because staged rows never carry splits/tags/transfers and their FKs are `ON DELETE SET NULL`. Guard tests cover field mapping + posted status. STAGING also DONE — the cross-existing dedup now prefetches the account's transactions once and matches in memory (was a range query per row) and staged rows are written with a chunked multi-row INSERT (was one per row); the dedup tests guard the matching logic. Both halves of the CSV import write-path are now set-based.
4. ~~SimpleFIN sync N+1~~ **DONE** — (a) correctness: partial unique index `uq_staged_external` (migration 125) + `ON CONFLICT DO NOTHING` so overlapping syncs can't double-stage; (b) perf: the per-transaction exact-dedup and category-inheritance queries are now prefetched once per book into an in-memory Set + Map, collapsing ~2 round-trips/row into O(1) lookups (the index-backed legacy fallback stays per-row, only for genuinely-new rows). Residual (bounded by account count, low priority): `recordSyncedBalance` (~4 queries/account) and `recordHoldings` (per-holding) loops.
5. **net-worth history correlated subqueries** (`networth.ts:45-208`) — `dates × entities` correlated `(SELECT … ORDER BY as_of DESC LIMIT 1)`. STATUS: perf mitigated by the migration-124 `(entity_id, as_of DESC, id DESC)` composites (each subquery is now an index lookup), and a **characterization test** (`networth.test.ts`, "over-time series forward-fills…") locks the exact `/over-time` + `/asset-history` + `/liability-history` output. **Date-axis monthly bucketing DONE** — all four over-time endpoints now select `max(as_of) … GROUP BY date_trunc('month', as_of)`, so the `dates` multiplier is capped at ~12/year instead of one-per-fact-date (a daily-synced account no longer explodes the series). Only the axis changed; the LOCF subqueries are untouched. A month with a single fact is unchanged (the forward-fill characterization test passes verbatim); dense months collapse to the latest fact date (new test covers it). The full set-based window rewrite remains DEFERRED (low marginal gain now that perf is mitigated by both the indexes and the bucketing; it must still faithfully reproduce the current/opening fallback-before-first-fact, the `as_of DESC, id DESC` tiebreak, voided/disposed handling, and the differing per-endpoint axes).
6. **`ACCOUNT_BALANCES`** (`effectiveLines.ts:63-96`, used by dashboard/accounts/networth/analysis). ALREADY OPTIMIZED on inspection: the anchor is the latest balance snapshot (or `opening_balance`) and the posted-delta sum is filtered to transactions dated *after* the anchor (`txn_date > anc.dt`) — i.e. snapshot + post-snapshot deltas, not a full-ledger re-aggregation. The inner per-account subquery still *reads* the account's full transaction list (the `posted_date IS NULL OR txn_date > anc.dt` OR prevents an index range, and `pending_extra` needs all unposted rows), but that's CPU-not-I/O and pushing the filter into the WHERE is a marginal, I/O-neutral gain on the core balance CTE — not worth the risk. The math is now locked by a characterization test (`accounts.test.ts`, "computed balance = snapshot anchor + post-anchor posted deltas (+ pending)"). The only materially faster path is a cached `posted_balance` column maintained on every write (imports/sync/transfers/disposals) — DEFERRED: real write-path-consistency risk for modest gain given the anchor + indexes already make this acceptable, and now the test would guard any such rewrite.
7. **Silent hard caps → real (keyset) pagination:** the per-entity detail aggregates are fixed (see C4), but the book-wide LIST endpoints still cap: `utilities.ts` `/invoices` (LIMIT 500, book-wide list view), `subscriptions.ts:337` `/charges` (LIMIT 2000, now unused by the UI but still exposed), `tags.ts:145` (LIMIT 500), `transactions.ts:368` (LIMIT 5000 /similar); also paginate the unbounded per-account history (`accounts.ts:165/242/255`).
8. **`GET /api/transactions` runs two full `count(*)` per load** (`transactions.ts:261-274`) — replace with `limit+1` hasMore or count only on page 1.
9. **Optional global `statement_timeout`** for non-job requests (kept off now so backup/import aren't killed; gate those jobs separately).

2. ~~Entity-detail txn lists use `limit=200` and silently drop rows.~~ **DONE** (see follow-up pass above).
3. **Net-worth history charts uncapped** (`Dashboard.tsx:43`, `Assets.tsx:43`, `Liabilities.tsx:54`): add a `months`/range param + default window (mirror the cash-flow `?months=12`).

6. **Unbounded rendered lists.** Tackled dependency-free via pagination rather than adding a virtualization library. DONE: the **Categories tag report** now paginates its transaction list (`/tags/:id/report` takes `limit`/`offset` and returns `transactions_total`; the aggregates stay full-set; the modal uses the shared `<Pager>`) — removes the silent 500-cap truncation and bounds the DOM; covered by a new `tags.test.ts`. ### C. Correctness / hardening (remaining)
1. **Timezone-aware "today".** BUDGET PERIODS + GOALS DONE — `BudgetDetail` sends the browser-local date as `ref` to `/budgets/:id/progress` and the drill-down `TxnModal`; `/goals` now accepts a `ref` param (`resolveProgress` takes a `today` arg) and `Goals` sends the local date, so reduce-spending goals resolve the current period in the user's zone. New-transaction dates are already local (`TxnEditor` defaults `txn_date`/`posted_date` to local `todayStr()`; the backend UTC fallback only fires for a client that omits the date — API callers). **Remaining:** SimpleFIN epoch→date (`connections.ts:168`, backend-only — needs a per-account/user tz) and the latent `budgets.ts periodWindow` local-parse/UTC-format mix (only bites on a non-UTC *server*). A per-user timezone setting would resolve both centrally.
2. **Write-route validation gaps** — PARTIALLY DONE: `insuranceRoutes.ts` (premium/deductible→`optionalMoney{min:0}`, cycle enum, dates, capped text), `subscriptions.ts` /suggestions/confirm (now validated), `vehicles.ts`/`properties.ts` loan/mortgage opening balance (→`optionalMoney{min:0}`), and `auth.ts` profile (→`isFinite` + non-negative) are fixed. **Remaining:** `assets.ts:134-166` maintenance cost; `properties.ts:240,272` hoa_cycle enum; the broad unbounded-TEXT sweep (`optionalString({max})` on the many free-text columns); and adding `{min:0}`/`{max}` to the remaining `optionalMoney` calls across vehicles/assets/liabilities/properties create/update.
3. **Concurrency / idempotency:** DONE — vehicle disposal idempotency (`FOR UPDATE` + already-disposed 409); manual balance snapshot now serialized with `SELECT … FOR UPDATE` on the account row; `applyTransactionToInvoices` candidate read now `FOR UPDATE OF i`; `POST /:id/category` no longer advances subscription due dates (it never changes tags — that drifted `next_due_date` on every call/double-click). **Remaining:** SimpleFIN double-stage (needs the unique index + `ON CONFLICT`, see A4); balance-snapshot still appends a `balance_events` row even when the value is unchanged (cosmetic — net worth picks the latest event per date, not a sum).
4. ~~Aggregations over truncated sets report WRONG totals.~~ **DONE** — SubscriptionDetail now reads a new `GET /subscriptions/:id/charges` that returns an exact SQL `SUM`/`COUNT` (covered by a test); UtilityAccountDetail now fetches `/utilities/invoices?account_id=…` uncapped (the route drops the 500 cap when scoped to one account), so its billing stats match the account's SQL totals.
5. ~~`assertSplitTotal` tolerance ±0.01~~ **DONE** — tightened to ±0.005 (half-cent; absorbs float noise, not a real 1¢ mismatch).
6. **Receipts/files at scale.** PER-FILE SIZE LIMIT DONE — `assertUploadSize` (`uploads.ts`, 15 MB cap, unit-tested) now runs at all 17 upload sites alongside the MIME check, so a single base64 blob can't bloat a DB row / backup envelope / the AI-image-in-memory path. **Per-book quota: deliberately NOT implemented.** A hard cap on total files/bytes per book would *cap legitimate long-term use* — directly at odds with the product's promise of holding years of receipts — and a meaningful total either costs an expensive per-upload scan (detoasting blobs) or needs a maintained counter (the same write-path-cache risk as A6). For a self-hosted single-family app (not an abuse-prone public multi-tenant SaaS), the per-file cap is the right protection. The real scaling path is offloading blobs to object storage — a deploy/infra change, out of scope here.
7. ~~Polymorphic `line_tags` not cleaned on entity delete~~ **DONE** — vehicle/property delete now removes their `line_tags` in the same transaction.
8. ~~`markLinkError` swallowed~~ **DONE** — now logs the write failure and the original error instead of an empty catch.
